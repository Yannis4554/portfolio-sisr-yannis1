Active Directory — Labannu & Labannubis

Déploiement de 2 contrôleurs de domaine en réplication sur Nutanix. Configuration complète d'AD DS : unités d'organisation, comptes utilisateurs, groupes de sécurité et GPO. Basculement automatique sur DC2 en cas de panne du DC principal.

Windows Server Active Directory Nutanix AD DS GPO DC1 / DC2

Labannu — DC1 (192.168.250.98) — Contrôleur de domaine principal. Installation du rôle AD DS, création du domaine labannu.local, mise en place des UO, comptes utilisateurs et groupes de sécurité. Détenteur de tous les rôles FSMO.

Labannubis — DC2 (192.168.250.100) — Contrôleur de domaine secondaire. Réplication AD DS bidirectionnelle avec DC1. En cas de panne de Labannu, Labannubis assure la continuité d'authentification sans interruption.

Validation : connexion réussie depuis un poste client Windows 10/11 avec les comptes AD.

DC1 Labannu → 192.168.250.98
DC2 Labannubis → 192.168.250.100
Réplication AD DS → automatique bidirectionnelle
Rôles FSMO → DC1 (PDC, RID, Infra, Schema, Naming)

DNS Primaire & Secondaire — Haute Disponibilité

Configuration d'un serveur DNS primaire sur Labannu et d'un DNS secondaire sur Labannubis. La zone secondaire se synchronise automatiquement depuis le primaire, assurant la résolution interne même en cas de panne du DNS principal.

DNS primaire DNS secondaire Windows Server Zone secondaire Haute disponibilité labannu.local

DNS Primaire — Labannu (192.168.250.98) — Héberge la zone principale labannu.local. Gère l'ensemble des enregistrements A, PTR et SRV du domaine. Seul serveur autorisé à modifier la zone.

DNS Secondaire — Labannubis (192.168.250.100) — Héberge une copie en lecture seule de la zone primaire. Transfert de zone automatique depuis Labannu. En cas de panne du DNS primaire, Labannubis répond aux requêtes de résolution sans interruption.

Validation : résolution du domaine labannu.local fonctionnelle depuis les postes clients, même avec Labannu hors ligne.

Zone primaire → labannu.local (Labannu — 192.168.250.98)
Zone secondaire → labannu.local (Labannubis — 192.168.250.100)
Transfert de zone → automatique depuis le primaire
Enregistrements → A, PTR, SRV (Kerberos, LDAP…)

Serveur DHCP — Debian 12

Installation et configuration d'un serveur DHCP sous Debian 12 avec isc-dhcp-server. Définition des plages, réservations MAC, options de bail, DNS et passerelle. Validation avec attribution automatique depuis les postes clients.

Debian 12 isc-dhcp-server IPv4 Linux Réseau local

Déploiement sur Debian 12 via apt install isc-dhcp-server. Configuration du fichier /etc/dhcp/dhcpd.conf : subnet, plage dynamique, bail de 24h, option routers (passerelle), option domain-name-servers (DNS). Activation de l'interface dans /etc/default/isc-dhcp-server. Vérification des attributions via /var/lib/dhcp/dhcpd.leases.

Haute Disponibilité — Keepalived & LVS

Architecture haute disponibilité complète sur Nutanix : 2 directeurs LVS en MASTER/BACKUP, IP virtuelle VRRP, 2 serveurs web avec synchronisation rsync. Basculement automatique en cas de panne du nœud principal.

Keepalived LVS / IPVS VRRP rsync Debian 12 Nutanix

Architecture : Le Directeur MASTER (priorité 100) distribue les requêtes entre les 2 serveurs web via Round Robin NAT. En cas de panne, le BACKUP (priorité 80) récupère automatiquement l'IP virtuelle grâce à VRRP. Les serveurs web synchronisent leurs données via rsync pour assurer la cohérence.

Validation : Le client accède au site via 172.31.1.70 (VIP). Même après extinction du MASTER, le service reste disponible sans interruption.
